# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project Overview

Intent UI is a React component library built on React Aria Components with Tailwind CSS. It provides 87+ accessible, customizable components distributed via a shadcn-compatible registry system.

## Essential Commands

```bash
# Development
npm run dev              # Start dev server with Turbopack
npm run build            # Production build (runs prebuild steps automatically)
npm run preview          # Build and start production server

# Code Quality
npm run lint             # Run Biome linter
npm run format           # Fix lint issues and format code
npm run typecheck        # TypeScript type checking

# Registry (run after modifying components)
npm run r                # Shortcut for registry:generate
npm run registry:generate # Full registry rebuild

# Validation Scripts
npm run cuc              # Check "use client" directives
npm run cdc              # Check for duplicated Tailwind classes
```

## Architecture

### Directory Structure

- `src/components/ui/` - Core UI components (button, modal, table, etc.)
- `src/components/examples/` - Demo components organized by category (buttons/, forms/, overlays/, etc.)
- `src/content/docs/` - MDX documentation files
- `src/lib/` - Utility functions (filters, helpers, theme utils)
- `src/hooks/` - Custom React hooks
- `src/scripts/` - Build scripts for registry, search, and stubs
- `src/stubs/` - Installation templates (.stub files) for different frameworks
- `__registry__/generated.ts` - Auto-generated component registry (do not edit)

### Registry System

The registry is central to how Intent UI works. When you modify components:

1. Components in `src/components/ui/` are automatically discovered
2. `generate-registry.ts` analyzes imports to build dependency graphs
3. `shadcn build` processes the registry for CLI distribution
4. Output goes to `registry/` and `__registry__/generated.ts`

**Always run `npm run r` after modifying components** to update the registry.

### Component Patterns

Components follow these conventions:

- Built on React Aria Components for accessibility
- Styled with `tailwind-variants` (tv) for variant management
- Use CSS variables for theming (defined in `src/styles/`)
- Require "use client" directive for interactive components

Example component structure:

```tsx
'use client'

import { tv } from 'tailwind-variants'
import { Button as ButtonPrimitive } from 'react-aria-components'

const buttonStyles = tv({
  base: '...',
  variants: {
    intent: { primary: '...', secondary: '...' },
    size: { sm: '...', md: '...', lg: '...' },
  },
})
```

### Styling System

- Tailwind CSS v4 with CSS custom properties
- Theme tokens: `--color-primary`, `--color-secondary`, `--radius-lg`, etc.
- 12 color themes available (default, blue, emerald, purple, etc.)
- Light/dark mode via CSS variable swapping

### Documentation

- Uses Fumadocs for MDX documentation
- Docs in `src/content/docs/` with frontmatter (title, description, order)
- Demo files in `src/components/examples/[category]/` are auto-discovered
- Search index generated by `generate-search.ts`

## Code Style (Biome)

- 2-space indent, no semicolons, 100-char line width
- Sorted Tailwind classes enforced for `tv()`, `twMerge()`, `composeRenderProps()`
- Organized imports required
- Arrow functions preferred

## Key Dependencies

- React 19, Next.js 16 (App Router)
- React Aria Components for accessibility primitives
- tailwind-variants for variant styling
- Fumadocs for documentation
- shadcn for registry/CLI tooling
